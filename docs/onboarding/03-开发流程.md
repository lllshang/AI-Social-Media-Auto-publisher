# 03 - 开发流程（轻量协作规范）

> 目标：让你写的代码能干净地合进项目，不把别人（和服务器）搞乱。
> 这是**正式规范**，第一次提交前务必读完。硬性原则标 🔴，建议标 🟢。

---

## 一、分支模型（🔴 必须遵守）

```
main            ← 生产发布分支，只接受来自 develop_P0 的发版合并，平时别直接碰
develop_P0      ← 集成分支，所有功能做完后合到这里，稳定后再发版到 main
feature/xxx     ← 你开发新功能时从 develop_P0 切出来的分支
fix/xxx         ← 修 bug 时从 develop_P0 切出来的分支
```

**日常开发流程：**
1. 开始一个任务前，先切到 `develop_P0` 并拉最新：`git checkout develop_P0 && git pull`
2. 从 `develop_P0` 切新分支：
   - 新功能：`git checkout -b feature/你的功能英文名`（例：`feature/tts-voice`）
   - 修 bug：`git checkout -b fix/登录报错`
3. 在这个分支上写代码、自测。
4. 完成后提交 PR（见下文），由负责人 review 后合进 `develop_P0`。

**🔴 禁止：**
- 直接在 `main` 或 `develop_P0` 上写代码（会被别人的更新冲掉，也容易误发版）。
- 把未测试的代码直接合进 `develop_P0`。

---

## 二、提交信息格式（🔴 必须遵守）

每次 `git commit` 的信息按类型开头，方便以后看历史：

```
feat: 新增 TTS 配音功能
fix: 修复发布任务卡在 pending 的问题
docs: 补充环境搭建文档
refactor: 重构素材服务层
chore: 升级依赖版本
```

格式：`<类型>: <一句话中文/英文说明，讲清楚改了啥>`

**好例子**：`fix: 小红书登录二维码超时导致发布失败`
**坏例子**：`update`、`改了点东西`、`fix bug`

---

## 三、提交前自检清单（🔴 合并前必须全过）

提交代码（或提 PR）前，逐条确认：

- [ ] 本地项目能正常启动，`http://127.0.0.1:8765/app/` 能登录
- [ ] 我改的功能手动点过，确实生效（不是「应该没问题」）
- [ ] 没有把 `.env` / `deploy.env` / Cookie 文件加进提交（🔴 泄露即事故）
- [ ] 没有把 `backend/.venv`、`web/node_modules`、`*.pyc`、`data/` 数据库加进提交
- [ ] 提交信息符合 `feat:/fix:/...` 格式
- [ ] 改了前端后跑了 `npm run build`

> 不确定有没有误加敏感文件？提交前用 `git status` 看一眼待提交列表，有 `.env` 之类立刻 `git reset` 撤回。

---

## 四、怎么提交 & 提 PR

```powershell
# 在 feature/xxx 分支上
git add .                       # 或只 add 你改的文件，别无脑 add 全部无关文件
git commit -m "feat: 你的说明"
git push origin feature/xxx
```

然后在 Git 仓库网页（公司 Git 平台）上：
1. 找到你的分支，点「New Pull Request / 合并请求」。
2. 目标分支选 `develop_P0`，来源选你的 `feature/xxx`。
3. 写清楚「这个 PR 干了什么、怎么测的」。
4. 指派给**负责人** review。

**🔴 谁来合并**：只有负责人 review 通过后才能合并。你不能自己点合并到 `develop_P0` / `main`。

---

## 五、遇到冲突怎么办（🟢 建议先问）

如果 `git pull` 或合并时提示冲突：
1. 不要慌，冲突只是「同一处代码两人都改了，Git 不知道留哪个」。
2. 用 VS Code 打开冲突文件，它会用颜色标出「你的」和「别人的」，你选要保留的。
3. 解决完 `git add 文件名` → `git commit` 完成合并。
4. 第一次冲突拿不准 → **截图问负责人**，别硬选。

---

## 六、常用 Git 命令速查

```powershell
git status                  # 看当前改了哪些文件（提交前必看）
git checkout develop_P0     # 切回集成分支
git checkout -b feature/xx  # 开新分支
git pull                    # 拉最新（切分支后第一件事）
git log --oneline -10       # 看最近 10 条提交历史
git diff                    # 看具体改了啥
```
