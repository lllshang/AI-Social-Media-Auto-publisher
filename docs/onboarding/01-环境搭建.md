# 01 - 环境搭建（Windows 从零）

> 目标：第一天结束，能在自己电脑上把项目跑起来，打开管理后台登录成功。
> 全程用 PowerShell（就是 Windows 那个蓝底/黑底的终端）。右键「开始」菜单 →「终端」或「Windows PowerShell」即可打开。

---

## 0. 先确认你有什么

打开 PowerShell，逐行输入，看版本：

```powershell
git --version      # 应该有输出，比如 git version 2.45.0
python --version   # 应该是 Python 3.11.x 或更高
node --version     # 应该是 v18.x 或更高
```

- 三个都有 → 跳到 **第 2 节**。
- 哪个没有 → 看下面对应小节安装。

---

## 1. 安装基础软件

### 1.1 Git（没有才装）
1. 浏览器打开 https://git-scm.com/download/win
2. 下载 64-bit 安装包，双击一路 Next。
3. 安装时注意：**「Adjusting your PATH environment」选「Git from the command line and also from 3rd-party software」**（让 PowerShell 能用 git）。

**报错了怎么办**：装完后**重新打开** PowerShell 再试 `git --version`。还不行就重启电脑。

### 1.2 Python 3.11（没有或版本太低才装）
1. 打开 https://www.python.org/downloads/ ，下 **3.11.x** 的 Windows installer (64-bit)。
2. 双击安装，**第一屏务必勾选 `Add python.exe to PATH`**（最下面那行小字，很多人漏掉）。
3. 点 Install Now。

**报错了怎么办**：
- `python` 命令找不到 → 重装并勾选 Add to PATH；或手动把安装目录加进系统环境变量 PATH。
- 装完**重新打开 PowerShell** 验证 `python --version`。

### 1.3 Node.js 18（前端构建用，没有才装）
1. 打开 https://nodejs.org/ ，下 **LTS（18.x 或 20.x）** 的 Windows 安装包（`.msi`）。
2. 双击一路 Next。

**报错了怎么办**：装完重新打开 PowerShell，`node --version` 和 `npm --version` 都要有输出。

### 1.4 Google Chrome（扫码登录小红书用）
- 已经装了 Chrome 就跳过。
- 没装：https://www.google.com/chrome/ 下载安装。
- 本项目本地开发用本机 Chrome 弹窗扫码发小红书，所以必须有。

### 1.5 VS Code（强烈推荐写代码用）
- https://code.visualstudio.com/ 下载安装。
- 装好后建议装扩展：**Python**（Microsoft 出品）、**Volar**（Vue 官方）、**GitLens**。

---

## 2. 克隆项目代码

找一个你放代码的目录，比如 `D:\code\`。在 PowerShell 里：

```powershell
cd D:\code
git clone <仓库地址> AI-Social-Media-Auto-publisher
cd AI-Social-Media-Auto-publisher
```

> `<仓库地址>` 问负责人要（公司 Git 仓库的地址）。如果是第一次 clone，会让你输入账号密码或配置 SSH key，按提示操作即可。

**报错了怎么办**：
- `Permission denied (publickey)` → 仓库用的是 SSH 地址但你没配 key。让负责人给你「HTTPS 地址」再 clone，或教你怎么生成 SSH key 加到仓库。
- 网络慢 → 公司内网仓库正常；公网慢就重试，或问负责人要离线包。

---

## 3. 配置本地环境变量

项目用 `.env` 文件存配置（数据库地址、密钥等）。仓库里给的是 `.env.example` 模板，你需要复制一份成 `.env`：

```powershell
cd ai-publish
copy .env.example .env
```

> `.env` 已经在 `.gitignore` 里被忽略，不会误提交，放心复制。

**这步一般不用改内容**，默认就是本地开发配置（SQLite 数据库、本机 Chrome）。如果负责人给了特殊配置，他会单独告诉你改哪几行。

**报错了怎么办**：`copy` 报「系统找不到指定的路径」→ 确认你 `cd ai-publish` 成功了（看到 `ai-publish` 目录在 `D:\code\AI-Social-Media-Auto-publisher\ai-publish` 下）。

---

## 4. 构建前端页面

前端（Vue）需要先「构建」成静态文件，后端才能托管它。

```powershell
cd ai-publish\web
npm install      # 第一次需要，装依赖，可能要几分钟
npm run build    # 构建，生成 web/dist 目录
```

**报错了怎么办**：
- `npm install` 卡住/超时 → 可能网络问题。问负责人要不要配国内 npm 镜像（淘宝源）。
- 报 `node-sass` / `sass` 编译错 → 确认 Node 是 18/20 LTS，不是太新的实验版。
- 构建成功后，`web\` 下会多一个 `dist` 文件夹，这是正常的。

---

## 5. 启动后端 + 打开管理后台

回到 `ai-publish` 目录，用项目自带的 Windows 启动脚本：

```powershell
cd ai-publish
.\start.ps1
```

这个脚本会：自动建 Python 虚拟环境 → 装后端依赖 → 读 `.env` → 启动 API 服务（默认端口 8765）。

第一次运行会装一堆 Python 包，可能要 **3~5 分钟**，请耐心等，看到下面这样的输出就是成功了：

```
 API 多平台内容自动发布系统 — MVP
 API 文档:  http://127.0.0.1:8765/docs
 管理后台:  http://127.0.0.1:8765/app/
 健康检查:  http://127.0.0.1:8765/health
 默认账号:  admin / admin123
```

**然后**：打开浏览器，访问 **http://127.0.0.1:8765/app/** ，用 `admin / admin123` 登录。

能登录 = 环境搭建成功 🎉

**报错了怎么办**：
- 浏览器打不开 / 连接被拒绝 → 看 `start.ps1` 那个窗口有没有报错。常见是依赖没装完（杀毒软件拦截、网络超时）。把报错发给负责人。
- 端口被占用 → 关闭占用 8765 端口的程序，或问负责人怎么改端口。
- PowerShell 报「禁止运行脚本」→ 以**管理员**打开 PowerShell，执行 `Set-ExecutionPolicy -Scope CurrentUser RemoteSigned`，输入 `Y` 回车，再重跑 `.\start.ps1`。

---

## 6. 日常开关机（记住这两条）

- **启动**：每次开发前，PowerShell 里 `cd ai-publish` 然后 `.\start.ps1`，保持这个窗口开着。
- **停止**：在 `start.ps1` 那个窗口按 `Ctrl + C`。
- 改了前端代码（web/ 下）要重新 `npm run build` 才生效；改了后端代码脚本带 `--reload` 会自动重启。

## 7. （部署才需要）安装 WSL2

> **本机开发用不到 WSL2**，只有「要部署到服务器」时才需要（因为部署脚本是 bash 写的，Windows 原生跑不了）。你现在可以先跳过，等 D3 部署那天再看。

为什么需要它：项目部署脚本 `sync-to-server.sh` / `deploy-tencent.sh` / `upgrade.sh` 都是 Linux bash，且依赖 `rsync`。**Windows 原生没有 rsync**，Git Bash 也常缺组件。最省事稳妥的办法是在 Windows 里装一个 Linux 子系统（WSL2 Ubuntu），只在「要部署」时进 WSL 执行脚本，和你负责人在 Mac 上的流程完全一致。

**安装（一条命令，需管理员 PowerShell）**：

```powershell
# 用管理员身份打开 PowerShell（右键开始菜单 → 终端(管理员)）
wsl --install
```

装完会提示重启电脑。重启后首次打开会让你设一个 Linux 用户名和密码（记住它）。

**日常怎么用 WSL 部署**（D3 再细看 `04-部署上线.md`）：
```powershell
# 普通 PowerShell 里进入 WSL
wsl
# 进入 WSL 后，你的 Windows 磁盘在 /mnt/ 下，比如 D 盘：
cd /mnt/d/code/AI-Social-Media-Auto-publisher/ai-publish/scripts
bash sync-to-server.sh
```

> 提示：WSL 里执行 `bash xxx.sh` 就能跑和负责人 Mac 上一模一样的部署脚本，出问题负责人能直接在 Mac 上复现。
