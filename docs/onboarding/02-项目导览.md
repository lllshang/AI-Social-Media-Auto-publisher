# 02 - 项目导览

> 目标：读懂系统由哪几块组成、代码怎么分层、一次「点按钮」是怎么一路走到数据库的。读完你能定位「我要改的功能在哪个文件」。
> 建议配合在编辑器里打开代码一起看。

---

## 一、系统到底在做什么（再复习一遍）

```
用户在前台操作（写主题 / 选平台 / 点生成 / 建发布任务）
   ↓
Vue 管理后台 (web/)               —— 用户看到的花花绿绿的界面
   ↓ HTTP 请求
后端 API (backend/app/api/)       —— 接收请求，做参数校验、权限检查
   ↓ 调用
业务服务层 (backend/app/services/) —— 真正的业务逻辑：生成文案、管理素材、调度发布
   ↓ 调用
适配器层 (backend/app/adapters/)  —— 对接外部：AI 厂商、各平台 Playwright 发布器
   ↓
数据库 (MySQL/SQLite) + 素材存储   —— 数据落地
```

人话版：用户在网页上点几下，后端帮它调 AI 写出内容、存好图片视频、然后用浏览器自动化模拟人工把内容发到小红书/抖音/快手。

## 二、目录结构（你每天会碰的）

```
AI-Social-Media-Auto-publisher/      ← 仓库根目录
├── ai-publish/                      ← 主应用（你主要改这里）
│   ├── backend/                     ← 后端（FastAPI，Python）
│   │   └── app/
│   │       ├── main.py              ← 程序入口，注册所有路由、启动配置
│   │       ├── api/                 ← 接口层：每个文件=一类功能的 HTTP 接口
│   │       │   ├── create.py        ← 创建发布任务
│   │       │   ├── materials.py     ← 素材管理
│   │       │   ├── auth.py          ← 登录/权限
│   │       │   ├── publish_tasks.py ← 发布任务
│   │       │   └── ...              ← 账号、审核、日志、看板等
│   │       ├── services/            ← 业务层：接口层调用的逻辑实现
│   │       ├── adapters/            ← 适配器：对接 AI 厂商 / 平台发布器
│   │       ├── models/              ← 数据库表定义（SQLAlchemy）
│   │       ├── schemas/             ← 接口的输入输出数据格式
│   │       ├── config.py            ← 读取 .env 配置
│   │       └── database.py          ← 数据库连接
│   ├── web/                         ← 前端（Vue3，你看到的界面）
│   │   ├── src/views/               ← 各个页面（CreateView=创建页等）
│   │   ├── src/api/                 ← 前端调用后端的封装
│   │   └── dist/                    ← npm run build 生成的静态文件（不用手改）
│   ├── scripts/                     ← 部署脚本（bash，Windows 下用 WSL 跑）
│   │   ├── deploy-tencent.sh        ← 服务器首次/全量部署
│   │   ├── sync-to-server.sh        ← 从本机同步代码到服务器
│   │   └── upgrade.sh               ← 服务器上升级（日常发版）
│   ├── docker-compose.yml           ← Docker 部署编排
│   ├── .env.example                 ← 配置模板（复制成 .env 用）
│   ├── start.ps1                    ← Windows 本地启动
│   └── start.sh                     ← Mac/Linux 本地启动
├── vendor/
│   └── social-auto-upload/          ← 第三方参考项目（小红书 Playwright 发布器）
│                                     ← 一般不用改，后端通过 SAU_VENDOR_PATH 引用它
├── docs/                            ← 文档（你在看的这些 + deployment.md 运维手册）
└── openspec/                        ← 需求/规格文档（变更记录）
```

**记三个最关键的位置：**
- 改**界面**：`ai-publish/web/src/`
- 改**后端接口**：`ai-publish/backend/app/api/`
- 改**业务逻辑**：`ai-publish/backend/app/services/`

## 三、一个请求的完整链路（重点！跟着走一遍）

以「用户在前台点【生成文案】」为例，看代码怎么流动：

### 第 1 步：前端发请求
`web/src/views/CreateView.vue` 里有个按钮，点下去调用 `web/src/api/index.js` 里封装好的函数，向 `POST /api/...` 发 HTTP 请求。

> 想看前端怎么调后端的，搜 `web/src/api/index.js`，里面每个函数对应一个后端接口。

### 第 2 步：后端接口接收
请求到达 `backend/app/api/create.py` 里的某个函数（被 `@router.post(...)` 装饰）。它做三件事：
1. 用 `schemas/` 里的结构校验参数格式对不对；
2. 检查登录态（依赖 `dependencies.py` 里的鉴权）；
3. 把活儿交给 `services/` 层处理，自己不直接写业务逻辑。

### 第 3 步：业务层干活
`backend/app/services/create_service.py` 被调用，里面写「生成文案」的实际逻辑：调 AI 适配器拿文案、存进数据库、返回结果。

### 第 4 步：适配器对接外部
`backend/app/adapters/ai_text/` 真正去调通义/混元/OpenAI 的 API，把返回的文本整理好给回 service。

### 第 5 步：数据落地
service 用 `models/` 定义的表结构，通过 `database.py` 的会话把文案存进数据库。

### 第 6 步：结果返回
数据原路返回：service → api → 前端 → 页面上显示出生成的文案。

**你改功能时就是在这条链路上「插针」**：
- 改界面样子 → 动 `web/src/views/`
- 改接口参数 → 动 `api/` + `schemas/`
- 改业务逻辑 → 动 `services/`
- 改对接外部的方式 → 动 `adapters/`

## 四、几个必懂的概念

| 概念 | 是什么 | 在哪看 |
|------|--------|--------|
| **路由 / 接口** | 前端能调的后端入口，形如 `POST /api/materials` | `backend/app/api/*.py` 里的 `@router.xxx` |
| **Service** | 一段完整业务逻辑，被接口调用 | `backend/app/services/*.py` |
| **Adapter** | 对接外部系统（AI、平台）的适配层，隔离变化 | `backend/app/adapters/*` |
| **Model** | 数据库表，决定数据长啥样 | `backend/app/models/*.py` |
| **Schema** | 接口的输入/输出格式约定 | `backend/app/schemas/*.py` |
| **.env** | 配置中心：数据库地址、密钥、开关 | `ai-publish/.env`（本地）、`scripts/deploy.env`（部署） |
| **vendor** | 第三方小红书发布器，后端引用，一般不动 | `vendor/social-auto-upload/` |

## 五、D2 练手任务（可选但推荐）

挑一个最小改动验证你读懂了链路：
1. 在 `web/src/views/CreateView.vue` 找一句界面文字，改成别的，重新 `npm run build` → 刷新页面看生效了没。
2. 或在 `backend/app/api/system.py` 的某个接口里加一行 `logger.info("hello from 新人")`，重启后端，在启动窗口看有没有打印。

改坏了别怕——你本地改的，删掉重来就行，又不是服务器。
