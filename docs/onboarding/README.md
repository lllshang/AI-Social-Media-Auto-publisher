> 适用对象：刚加入项目、第一次接触本仓库的同学。
> 开发机系统：**Windows**。本文档所有本地命令默认 PowerShell，部署相关命令在 WSL2 中执行（详见 `01-环境搭建.md`）。
> 维护者：项目负责人。如有改动请同步更新本索引。

## 一、这是什么东西（30 秒看懂）

「AI 多平台内容自动发布系统」——一句话：**用 AI 帮你写文案、做图、生成视频，然后自动发到小红书 / 抖音 / 快手等平台。**

完整链路：

```
用户在前台点「生成文案」
   → Vue 管理后台（web/）
   → 后端 API（backend/app/，FastAPI）
   → 业务服务层（services/）
   → AI 适配器（adapters/，对接通义/混元/OpenAI 等）
   → 素材存数据库 + 对象存储
   → 用户建「发布任务」
   → Playwright 自动登录账号、填内容、发布
```

你平时改的就是这几层。具体怎么串起来，看 `02-项目导览.md`。

## 五、⚠️ 红线清单（拥有生产服务器权限，必须先读）

你已拥有**直接操作生产服务器的权限**。以下操作出事就是客户数据永久丢失或线上事故，**无条件禁止 / 必须确认**：

| 等级 | 操作 | 说明 |
|------|------|------|
| 🔴 **永久禁止** | 在服务器上 `docker compose down -v` | `-v` 会删掉 MySQL/Redis 数据卷，**客户发布记录、账号 Cookie 全没了**，无法恢复 |
| 🔴 **永久禁止** | 在服务器上直接 `vim` 改代码 | 下次 `sync-to-server.sh` 会被覆盖，改了也白改，还可能和 Git 冲突 |
| 🔴 **永久禁止** | 提交 `.env` / `deploy.env` / Cookie 文件到 Git | 含密钥和账号信息，泄露即安全事故。这些文件已在 `.gitignore` 忽略，但**手动 `git add -f` 同样危险** |
| 🟡 **必须确认** | 生产部署前，先在群里说一声「我要发版了，预计 X 分钟」 | 让负责人知情，方便出现事故时有人接应 |
| 🟡 **必须确认** | 改 `API_PORT` / `PUBLIC_HOST` / 数据库配置前，先和负责人确认 | 改错会导致服务起不来或对外地址错误 |
| 🟢 **建议** | 任何 destructive 命令（带 `rm -rf`、`drop`、`:(){:|:&}`）先复制到记事本、读完再执行 | 慢一步，少一夜 |

**记住一条铁律：服务器上只跑部署脚本，不碰业务代码；改代码只在本地 + Git 提交。**
