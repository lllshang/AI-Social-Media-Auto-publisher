# 04 - 部署上线

> 目标：把本地写好的代码发到服务器上，让客户能访问。
> ⚠️ 你拥有生产服务器权限，动手前**务必先读 [README.md 红线清单](./README.md#四红线清单拥有生产服务器权限必须先读)**。铁律：**服务器只跑部署脚本，不碰业务代码；改代码只在本地 + Git 提交。**

部署脚本是 Linux bash，Windows 跑不了。所以你要在 **WSL2**（第 1 天装好的，见 `01-环境搭建.md` 第 7 节）里执行它们，和你负责人在 Mac 上的流程**完全一致**。

---

## 〇、部署前必做（每次都做）

1. ✅ 代码在 `develop_P0` 上已合并、自测通过（见 `03-开发流程.md`）。
2. ✅ 本地 `.\start.ps1` 跑过，功能正常。
3. ✅ 在群里说一声：「我要发版了，预计 X 分钟，期间服务可能短暂重启」。
4. ✅ 确认 `scripts/deploy.env` 里的 `PUBLIC_HOST` 是**目标服务器**的地址（发错服务器就尴尬了）。

---

## 一、场景 A：日常发版到「已有」的服务器

适用：服务器之前已经部署过，只是更新代码。

### 步骤 1：进 WSL，切到项目部署脚本目录
```powershell
# 普通 PowerShell 里
wsl
# 进入 WSL 后（Windows 磁盘在 /mnt/ 下，假设项目在 D 盘）
cd /mnt/d/code/AI-Social-Media-Auto-publisher/ai-publish/scripts
```

### 步骤 2：本机构建前端 + 同步代码到服务器
```bash
bash sync-to-server.sh
```
这个脚本会：构建 `web/dist` → 用 rsync 把 `ai-publish/` 和 `vendor/` 同步到服务器（保留服务器数据，不会删库）。

> 首次需要配 `deploy.env`（见下方「配置文件」）。之后直接跑即可。

### 步骤 3：SSH 进服务器，跑升级脚本
```bash
# 用 deploy.env 里的 SSH_USER 和 PUBLIC_HOST
ssh ubuntu@<服务器IP>
cd /opt/ai-publish/ai-publish
bash scripts/upgrade.sh
```

`upgrade.sh` 会重启 API/Worker 容器（保留 MySQL/Redis 数据卷），装好 Playwright 浏览器。

### 步骤 4：验收
浏览器打开 `http://<服务器IP>:8000/app/`，能登录、功能正常，即发版成功。
健康检查：`http://<服务器IP>:8000/health`

**报错了怎么办**：
- `rsync: command not found` → 在 WSL 里装：`sudo apt update && sudo apt install -y rsync`
- SSH 连不上 → 确认服务器开机、安全组/防火墙放行 22 端口、IP 没变。
- 升级后页面打不开 → 服务器上看日志：`docker compose logs -f api`，把报错发给负责人。
- 升级后功能不对 → 先别急着重来，看日志定位；需要回滚见「场景 C」。

## 二、场景 B：全新服务器从零部署

适用：买一台新服务器（比如腾讯云轻量应用服务器），第一次部署。

### 步骤 1：买机器 + 放行端口
1. 腾讯云控制台买一台 Ubuntu 22.04/24.04 的机器（建议 4G 内存起，2G 也能跑但慢）。
2. **防火墙 / 安全组**放行端口：`22`（SSH）、`8000`（API，或你设的 `API_PORT`）。有域名+HTTPS 再放 `80/443`。

### 步骤 2：配置本机 deploy.env
在 WSL 里编辑项目里的 `scripts/deploy.env`（没有就先复制模板）：
```bash
cd /mnt/d/code/AI-Social-Media-Auto-publisher/ai-publish/scripts
cp deploy.env.example deploy.env
notepad.exe deploy.env     # 用 Windows 记事本打开编辑，或用 WSL 里的 vim/nano
```
至少改这几项（其余看模板注释）：
```
PUBLIC_HOST=<新服务器公网IP>          # 或域名（不带 http://）
API_PORT=8000
SSH_USER=ubuntu                      # 腾讯云 Ubuntu 镜像默认用户
ADMIN_PASSWORD=<设一个强密码>         # 别用默认的 change-me
```
保存。

### 步骤 3：SSH 进新服务器，装 Docker
```bash
ssh ubuntu@<新服务器IP>
# 在服务器上执行安装脚本（脚本已随项目提供）
cd /opt/ai-publish 2>/dev/null || true
# 先确保本机已同步过代码（见步骤4），或手动把 install-docker-ubuntu.sh 传上去执行：
# 这里推荐：先在 WSL 跑一次 sync-to-server.sh（会建好 /opt/ai-publish 目录并传脚本）
```

实际顺序建议：**先跑步骤 4 的 sync 把脚本传上去**，再 SSH 进服务器装 Docker：
```bash
# 服务器上
cd /opt/ai-publish/ai-publish/scripts
bash install-docker-ubuntu.sh
# 装完按提示 exit 重新 SSH 登录，让 docker 组生效
```

### 步骤 4：本机同步代码 + 首次部署
回到 WSL（你自己的电脑）：
```bash
cd /mnt/d/code/AI-Social-Media-Auto-publisher/ai-publish/scripts
bash sync-to-server.sh        # 把代码传到服务器
```
SSH 进服务器执行首次部署：
```bash
ssh ubuntu@<新服务器IP>
cd /opt/ai-publish/ai-publish
bash scripts/deploy-tencent.sh
```
这个脚本会：检查 Docker → 拉国内镜像（若开启）→ 构建前端（若缺 dist）→ `docker compose up -d --build` → 装 Playwright 浏览器。

### 步骤 5：验收
- 管理后台：`http://<新服务器IP>:8000/app/`
- 用 `deploy.env` 里设的 `ADMIN_USERNAME` / `ADMIN_PASSWORD` 登录。
- 健康检查：`http://<新服务器IP>:8000/health`

**报错了怎么办**：
- `docker: command not found` → 步骤 3 的 Docker 没装好，重跑 `install-docker-ubuntu.sh` 并重新登录 SSH。
- `permission denied` 操作 `/opt` → 脚本用 `sudo rsync` 同步，确认你 SSH 用户有 sudo 权限（腾讯云 ubuntu 默认有）。
- 容器起不来 → `docker compose logs -f api` 看具体报错。
- 换 IP/域名 → 改 `deploy.env` 的 `PUBLIC_HOST`，必要时改 `USE_HTTPS` / `API_PORT`，再跑一次 `bash scripts/deploy-tencent.sh`。

## 三、场景 C：出事了怎么回滚

> 🔴 **最重要的底线**：回滚 = 用旧代码重新部署，**绝不**用 `docker compose down -v`（会删数据）。

如果新版本有严重 bug：

**方法 1（推荐，最快）：Git 回退代码再重新同步**
```bash
# 本地 WSL 里，切到上一个好版本对应的 commit
git -C /mnt/d/code/AI-Social-Media-Auto-publisher log --oneline -10   # 找到好版本的 commit hash
git -C /mnt/d/code/AI-Social-Media-Auto-publisher checkout <好版本hash>
cd /mnt/d/code/AI-Social-Media-Auto-publisher/ai-publish/scripts
bash sync-to-server.sh
# 服务器上
ssh ubuntu@<IP>
cd /opt/ai-publish/ai-publish && bash scripts/upgrade.sh
```

**方法 2：Docker 镜像回退**（如果你之前 `docker tag` 留了旧镜像）
```bash
# 服务器上
docker compose up -d api worker   # 指定旧镜像版本（需提前规划镜像 tag）
```

> 若数据库结构也跟着变了导致回不去，立刻在群里 @ 负责人，不要自己折腾 `drop` 表。

## 四、配置文件速查

| 文件 | 在哪 | 作用 | 能否提交 Git |
|------|------|------|--------------|
| `ai-publish/.env` | 本地 / 服务器 | 运行时配置（数据库、密钥、开关） | 🔴 禁止（含密钥） |
| `ai-publish/scripts/deploy.env` | 本机 | 部署目标配置（服务器 IP、端口、管理员） | 🔴 禁止（含密码） |
| `ai-publish/.env.example` | 仓库 | 配置模板（无密钥） | ✅ 可以 |

> 这两个 `.env` / `deploy.env` 已在 `.gitignore` 忽略。**永远不要 `git add -f` 它们。**

## 五、常用运维命令（在服务器上执行）

```bash
docker compose ps               # 看哪些容器在跑
docker compose logs -f api      # 实时看后端日志（Ctrl+C 退出）
docker compose restart api      # 单独重启后端
docker compose up -d --build api  # 改了 requirements/Dockerfile 后重建
```
